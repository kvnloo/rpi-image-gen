cloud-init for rpi-image-gen

Sample skeleton for using cloud-init with rpi-image-gen. Partially borrowed from the pi-gen cloud-init configuration.

Scope

This contribution is a NoCloud example for first-boot customisation of images built from a minimal base with rpi-image-gen. For modifying a full official Raspberry Pi OS image, pi-gen is more suitable.

The example expects cloud-init seed data from separate CIDATA media as described below.

This example and pi-gen's cloud-init support focus on first-boot customisation. Using cloud-init in a network-based cloud environment requires further configuration.

The image.json generated by rpi-image-gen is an Image Description Provisioning (IDP) document used by Raspberry Pi provisioning tooling. It is not a Raspberry Pi Imager customisation manifest and is not intended to enable Imager customisation.

An image must contain and enable a suitable integration for Imager-provided customisation data to take effect. For example, pi-gen's cloud-init setup provides seed files under /boot/firmware, rather than the separate media used here.

See the project provisioning documentation for the IDP format and scope.

Usage

  1. Fill in the applicable details in the config/pi-cloud-init.yaml.
  2. Build and provision the image as usual.
  3. On a FAT32 formatted USB drive with exactly the label CIDATA, add meta-data, network-config, and user-data. The details of what should be in those files can be found at https://cloudinit.readthedocs.io/, with sample files in this repo under the directory NoCloud-USB.
